# OneStudy Bot v3

Полный комплект исходников. Баннер исключён по просьбе владельца. Аватарка клиента используется только в рабочей карточке, когда Telegram разрешает получить фотографию.

## Обновление работающего бота — по порядку

1. **До обновления скачайте резервную копию существующей базы `threads.db` из постоянного хранилища Bothost.** Если бот работает во время копирования, лучше использовать созданную им резервную копию или остановить его перед скачиванием базы. Сохраните старую версию исходников.
2. Убедитесь, что в Bothost каталог `/app/data` подключён как **постоянное хранилище**. Одна переменная `DATA_DIR` не создаёт постоянный том. Если старая база лежит в другом месте, после остановки бота перенесите её в постоянный каталог под именем `threads.db`.
3. Остановите старый экземпляр. Один токен должен обслуживаться одним запущенным процессом. Не запускайте Mac-копию параллельно с Bothost.
4. Распакуйте архив. В корень GitHub-репозитория загрузите **содержимое папки `OneStudyBot_v3`**, а не саму папку целиком. Особенно важны `bot.py`, `db.py`, `facts.py`, `requirements.txt`, `Dockerfile`.
5. В Bothost сохраните `BOT_TOKEN` и `FORUM_CHAT_ID`. Добавьте **новую обязательную переменную `ADMIN_IDS`** — числовой Telegram ID менеджера, без `@`. Для нескольких разрешённых сотрудников — ID через запятую. Получить собственный ID можно, например, через Telegram-бота `@userinfobot`; отправляйте ему только обычное сообщение, токен OneStudy никому не нужен.
6. Укажите `DATA_DIR=/app/data`. Не вставляйте этот путь в `FORUM_CHAT_ID`! В последнем должен быть отрицательный ID рабочей группы.
7. Необязательно: `OWNER_CHAT_ID` — ваш личный Telegram ID. Сначала откройте OneStudy от этого аккаунта и нажмите `/start`. Тогда ошибки и ежедневная копия базы будут приходить вам лично. Без настройки ошибки приходят в рабочую группу; внешняя копия автоматически не создаётся.
8. Используйте сборку из `Dockerfile`, команда запуска — `python bot.py`. Уберите переопределение `python /app/server.py`, если оно осталось в настройках платформы. Выполните **пересборку из обновлённого репозитория**.
9. Бот должен быть администратором группы с включёнными темами, правами управления темами и закрепления сообщений. При запуске права проверяются.
10. Выполните проверку Telegram по списку ниже. До неё не направляйте в новую версию поток реальных клиентов.

Токен, `.env`, базы и резервные копии не загружайте в GitHub. В архиве секретов и клиентской базы нет. `.env.example` содержит только образцы.

## Перенос старой базы

Существующая таблица `threads` остаётся нетронутой. При первом запуске её текущие записи переносятся в новые таблицы. Открытые старые заявки получают статус «В работе», чтобы их случайно не архивировали. Завершённые сохраняют статус и оценку. Связи с имеющимися темами остаются.

Перенос идемпотентен: повторный запуск не создаёт второй набор заказов. Восстановить историю, которую старая версия уже перезаписала при новых заказах, программа не может. Номер темы и новый номер заказа различаются.

Для отката остановите v3 и восстановите **досохранённую старую базу вместе со старым кодом**. Новые заказы v3 не появятся в старой версии автоматически.

## Что реализовано

- Согласованное текстовое приветствие и постоянное главное меню.
- Необязательная анкета из пяти шагов, «Назад», «Пропустить», точная дата по Москве. Главное меню не сбрасывает анкету. Чтобы продолжить её после меню, нажмите «Новая заявка»: незавершённая анкета откроется повторно.
- Отдельные заказы, история, выбор прошлой заявки и несколько заказов на клиента.
- Закреплённая карточка с аватаркой, если она доступна, и безопасным отображением пользовательского текста.
- Передача текста, документов, фото, видео, голосовых, аудио, анимаций, стикеров, видеокружков, контактов, геопозиции. Опросы копируются, а при невозможности копирования передаются текстом. Игры, платные медиа и служебные сообщения не являются поддерживаемыми материалами.
- Постоянная очередь SQLite, повторные попытки, порядок внутри каждого направления заказа. Альбомы собираются коротким окном и передаются группами до 10 вложений.
- Одно приглашение нажать «Всё отправлено» на заказ; оно не подтверждает доставку заранее. После завершения передачи сообщение редактируется и показывает один факт.
- 45 фактов без повторов для клиента, пока не пройдена вся подборка. Неточные формулировки старой подборки исправлены; пример омофонов заменён на «плод / плот».
- Тихая передача дополнений. Новое уведомление при создании темы; серия не создаёт звук на каждый файл.
- Статусы и история изменений; внутренние `/note`; ограничения `/block`, `/unblock`.
- Экран заказов с фильтрами и страницами, поиск `/search`. «Сроки» сортирует все активные заказы с датой от ближайшей, включая просроченные.
- `/done` с подтверждением, одно сообщение с оценками 1/5–5/5, проверка владельца и повторного голосования, обратная связь.
- Напоминание через 30 минут от первого неотвеченного сообщения, без переноса отсчёта каждым дополнением.
- Предупреждение после 7 дней; архивирование после 30 дней только статусов «Новая» и «Уточняем». Заказы с недоставленными материалами не архивируются автоматически.
- Ежедневные согласованные копии SQLite, хранение последних 14 локальных файлов, необязательная отправка копии владельцу.
- Служебная тема с актуальной инструкцией.

## Команды менеджера

Только аккаунты из `ADMIN_IDS`, только рабочая группа:

- `/orders`, `/clients` — список и фильтры;
- `/search 1042`, `/search Анна` — поиск;
- `/done` — подтверждение завершения в теме;
- `/note текст` — внутренняя заметка, клиент не получает;
- `/retry` — повторить неудачные отправки этой темы;
- `/block`, `/unblock` — ограничить / разрешить входящие от клиента.

**Обычные сообщения в клиентской теме отправляются клиенту.** Анонимные сообщения от имени группы не принимаются как ответы менеджера: требуется личный разрешённый аккаунт. Отредактированные и удалённые сообщения не синхронизируются задним числом.

## Проверка после установки в Telegram

1. `/start`: приветствие, меню, отсутствие баннера.
2. Новая заявка: все пять шагов, возврат назад, пропуск, неправильная дата, файлы посреди анкеты.
3. Отправить 10 фото альбомом и ещё 10 документов; проверить количество и порядок в рабочей теме, отсутствие 20 ответов «Принято».
4. «Всё отправлено»: итоговое подтверждение только после доставки, один факт.
5. Ответить из темы; проверить доставку. `/note` клиенту не должен прийти.
6. Создать второй заказ; убедиться, что первый остаётся в «Мои заказы». Выбрать нужный заказ перед перепиской.
7. Перезапустить бот во время очереди; проверить продолжение передачи и сохранение анкеты.
8. Завершить через `/done`: подтверждение менеджеру, одно уведомление клиенту, компактная оценка.
9. Написать после закрытия несколько сообщений до выбора старого/нового заказа; после выбора проверить все сообщения.
10. Проверить недоступную аватарку, блокировку бота клиентом, отказ в действиях неразрешённому аккаунту.
11. Проверить перезапуск/пересборку с сохранением данных и пробное восстановление копии на отдельном экземпляре с другим тестовым токеном.

## Границы проверки и эксплуатации

Автоматические тесты используют имитацию Telegram API и настоящую SQLite; они не доказывают доступность Telegram из Bothost, правильность токена, права группы или реальное постоянство диска. Рабочего токена в среде сборки не было. Docker-движок для запуска контейнера здесь недоступен; Dockerfile проверен по составу и команде, а не живым запуском.

Нет гарантии exactly-once: если Telegram принял отправку, а процесс аварийно завершился до записи результата, после восстановления возможен дубль. Частично переданный альбом переводится в ошибку: менеджер проверяет тему перед `/retry`. Сохранённые file_id пригодны для того же Telegram-бота и не являются независимой копией файлов вне Telegram.

Напоминания пока круглосуточные — рабочий график не согласован. Бот не принимает платежи, не проверяет оплату автоматически и не рассчитывает реферальные скидки. Условия скидки не опубликованы до их уточнения. Автоматическое блокирование частых сообщений намеренно не включено: очередь ограничивает скорость передачи, ручной `/block` доступен.

Внешняя резервная копия требует `OWNER_CHAT_ID` и доступа бота к этому личному чату. При отсутствии настройки резервирование остаётся на том же диске. Telegram-копия базы содержит клиентские сведения — не пересылайте её посторонним.

## Локальный запуск и тесты

Python 3.11+; рабочий запуск — Linux/macOS (используется блокировка `fcntl`).

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -q
```

Для запуска задайте окружение по `.env.example`, для локального диска используйте `DATA_DIR=./data`:

```bash
.venv/bin/python bot.py
```

Не запускайте второй экземпляр с тем же токеном. При существующем webhook запуск остановится с понятной ошибкой: требуется переход на polling без удаления ожидающих обновлений.
