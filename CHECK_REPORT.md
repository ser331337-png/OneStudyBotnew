# Проверка OneStudy v3

Дата: 29.10.2026.

Проверка выполнена на Python 3.12.14 с aiogram 3.22.0. Исходники дополнительно проверяются парсером на синтаксис Python 3.11, который используется в Dockerfile.

## Автоматические проверки

Тесты находятся в `tests/test_system.py`; запускаются командой `pytest -q` после установки `requirements-dev.txt`.

Проверяются:

1. Несколько заказов на одного клиента и сохранение старых оценок.
2. Идемпотентный перенос старой таблицы `threads` с сохранением темы.
3. 20 файлов подряд, защита от повторной записи одного сообщения.
4. Сохранение сообщений до выбора старого/нового заказа, включая повторное открытие базы.
5. Восстановление состояния «передаётся» после перезапуска.
6. Отсутствие повторной отправки записей со статусом «доставлено».
7. 45 уникальных фактов и полный цикл без повторов.
8. Целостность резервной копии SQLite и наличие в ней заказов.
9. Проверка дат, включая несуществующие и прошедшие даты.
10. Аватарка, текстовая карточка без аватарки, редактирование подписи.
11. Экранирование пользовательского текста для HTML.
12. Обычное первое уведомление и тихие последующие.
13. Повтор после сетевого сбоя без удаления сообщения.
14. Сохранение ожидания ответа при недоставленном ответе менеджера.
15. Отправка альбома из сохранённых Telegram file_id.
16. Обнаружение неполной передачи альбома и перевод в ручную проверку.
17. Одно подтверждение на 20 входящих сообщений.
18. Проверка владельца заказа, диапазона и повторной отправки оценки.
19. Внутренние заметки, служебные команды и отказ постороннему аккаунту.
20. Подтверждение завершения и отсутствие второго уведомления при повторном нажатии.
21. Запрет автоматического завершения работающего заказа.
22. Сохранение времени первого неотвеченного сообщения при дополнениях.
23. Отказ устаревшей кнопке анкеты.
24. Передача всего пакета после выбора прошлого заказа.
25. Итоговое подтверждение после доставки и один выбранный факт.
26. Маршрутизация нескольких обновлений через настоящий Dispatcher aiogram.
27. Ответ менеджера не снимает ожидание более нового вопроса клиента.
28. Восстановление текстового сообщения, если исходное удалено в Telegram.
29. Запрет завершения при недоставленных сообщениях.
30. Главное меню сохраняет этап анкеты и выбранный заказ.
31. Сбой одного заказа не блокирует очередь другого.

Некоторые пункты объединены в одном тесте. Итоговое количество тестовых функций указывается в результате `pytest`.

## Дополнительные проверки

- Импорт модулей и компиляция Python.
- Согласованность установленных зависимостей: `pip check`.
- Состав ZIP: исходники, инструкции, тесты, оригинал логотипа; без `.env`, клиентской базы, кэша, виртуального окружения и баннера.
- Dockerfile: установка библиотек, копирование трёх рабочих модулей, команда `python bot.py`, постоянный путь `/app/data` задаётся окружением. Создание постоянного тома требует настройки Bothost.

## Что нельзя подтвердить без рабочего окружения

Живые запросы к Telegram, корректность токена, реальные права группы, получение конкретной аватарки, настройки постоянного хранилища Bothost и фактическая работа контейнера не проверены. Токен не предоставлялся; Docker Engine в среде отсутствует.

Перед использованием реальными клиентами выполните список приёмки в README.md. Абсолютная доставка без потерь и дублей при любых сбоях не обещается: Telegram не предоставляет транзакцию вместе с локальной SQLite.
